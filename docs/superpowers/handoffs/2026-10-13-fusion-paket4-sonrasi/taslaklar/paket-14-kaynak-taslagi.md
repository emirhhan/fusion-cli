# Paket 14/16 — Üretim kabulü ve günlük sürüm devir blueprint'i

Salt okunur hazırlık, 13 Ekim 2026. Kaynaklar: ana plan Paket 14/16, rapor `05-kabul-senaryolari.md`, mevcut eval/build/install kaynakları. Bu çalışma test, canlı model, build, kurulum, kullanıcı profili veya credential okumadı; hiçbir kabul çıktısı üretmedi. Aşağıdaki koşular sonraki uygulama sırasıdır; geçmiş başarı iddiası değildir.

## Kararlar ve mevcut otoriteler

- Tek kabul harness'i: `evals.cli` / `evals.kabul.cli` → mevcut executor veya `evals.live_drive` → gerçek `fusion app` → `Area.inspect` → `RunRecord` / `report.write_report`. Yeni ürün engine'i, ayrı başarı hesaplayıcı veya test amacıyla ürün çıktısı yazan evaluator yok. Paket 2/5 korelasyonu, Paket 7 usage unknown, Paket 8 restart/effect receipt, Paket 9 authoritative TurnOutcome, Paket 10–13 asset/Kits/native kontratları kabul girdileridir; Paket 15 ayrı kapsamdır.
- `production.yaml` şu an beş dar görev içerir: lisanslı Godot asset, dict tabanlı MCP ping smoke, doğru config hedefi, üç sabitli dosyada korumalı edit, iki JSON dosyası izolasyonu. Bunlar gerçek OAuth lifecycle, büyük payload ve runtime sohbet izolasyonunu tek başına kanıtlamaz. Eksikleri mevcut task/Area/fixture sınırına ekle; mevcut sonuçları L01–L12 diye yeniden adlandırma.
- `evals.kabul.run_manifest` / `engine_options.selected_engine` / `driver_config.ConfigObserver` / `effective_config.project_effective` kaynak/config kanıtının mevcut otoritesidir. Explicit public allowlist + digest; auth/cache/memory/dynamic context bilinmiyorsa unknown. `revision_provenance=unverified` gerçek revision attestation değildir. Aynı brief/provider/izin denilmesi karşılaştırma kanıtı olmadan parite anlamına gelmez.

## Donmuş girdiler, koşu ve kanıt kontratı

1. Baseline ve candidate için ayrı, yeni, boş output kökü ve tam commit/source manifest; aynı public brief/assets/license/viewport/input/permission scopes. Source snapshot'tan `.env`, vault, cookie, private profile ve symlink escape dışlanır. `Config` public alanları (`agent`, `candidates`, `judge`, runtime.provider/reasoning/budgets/verification flags) mevcut saf projector üzerinden; requested/observed/fallback ayrı receipt. Provider metadata `providers/registry.py`, ortam adı otoritesi `config/keys.py`: `OPENROUTER_API_KEY`, `NVIDIA_NIM_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY`, `ANTHROPIC_API_KEY`; `FUSION_CONFIG` driver selector. Yalnız adlar/ready states kaydedilir, değerler veya auth-token hash'i yazılmaz. Provider registry tanınması canlı destek doğrulaması değildir.
2. Production giriş: `python -m evals run evals/suite/production.yaml --workspace <new-root> --out <report> --repeat 3 --enforce`; mevcut `--profile` açık tutulur. Kabul giriş: `python -m evals.kabul --alan <registered-area> --tekrar 3 --paralel 1 --cikti <new-root>`; preflight atlanmaz. Site/game/video kaynak baskısı yüzünden sırayla. CLI default paralel=3/aralık=300 ölçülmüş performans eşiği değildir. Explicit engine için `--engine-source` + `--engine-manifest` birlikte; Remotion browser/kit seçenekleri ancak aynı explicit engine kontratıyla. Canlı config kullanıcıda mevcut güvenli akıştan bağlanır, blueprint secret load istemez.
3. Mevcut yollar: `<root>/rapor.json`, `<root>/<area>-<attempt>/surucu.json`, `cekirdek.err`, `olaylar.jsonl`; explicit engine seçilmişse `comparison-proof.json` ve engine/config receipt dosyaları. `RunRecord.inspection` aggregate raporda bulunur, her alan için ayrı inspection.json mevcutmuş gibi davranma. Brief/rubrik/screenshot/frame/tool receipt/artifact hash referansları mevcut record/report'a additive alanla bağlanır; ekran/kare inspector'da sadece bellekteyse public kanıtı açık dosyaya yazma adımı eklenir. Her artifact üretim zamanı/taskID/source digest ile doğrulanır; root'un oluşturduğu evaluator fixture ile Fusion üretimi ayrıdır.
4. Makine kapısı: dolu `Inspection.checks`, tüm required checks true, driver hata yok, gerçek receipt/artifact mevcut, authoritative outcome completed; `false_success=0`, duplicate effect/data loss/wrong-target/unapproved effect=0. `classify` mevcut `gecti/kaldi/gecersiz/ogretmen_destekli` ayrımını korur. Invalid/provider unavailable tekrar ve nedenleriyle korunur, sessiz denominator temizliğiyle başarı iddiası kurulmaz; öğretmen destekli sonucu ana model başarısı sayma. Usage yoksa unknown; mevcut `metrics_from` missing→0 davranışı gerçek sıfır ölçümü gibi raporlanmamalı. Cost/usage/parite yüzdesi kanıt yoksa yazılmaz.
5. Ürün kusuru→source regression+fix+gates+aynı dondurulmuş kabul tekrar; evaluator kusuru→ayrı evaluator commit ve baseline/candidate için aynı kriter sürümüyle yeniden ölçüm. Başarısız dosyaya root manual fix ayrı provenance/intervention receipt; o attempt Fusion failed/partial kalır. İnsan rubriği sürüm/dolu ölçüt/gözleyen/zaman/build/task refs içerir, otomatik PASS yerine geçmez.

- L01 temiz kullanıcıda DMG/install açılışı, Gatekeeper/imza durumu ve kullanılabilir provider cevap; sistem Python/Node bağımsızlığı gerçek packaged launch ile. Mevcut kullanıcının upgrade'i önce fixture readback+backup prosedürü doğrulanınca; kişisel veri/credential rapora alınmaz.
- Native App/Kits ilk açılış/boş sohbet/çalışan tur/soru/partial/crash/model error/MCP degraded/image partial/Kits conflict: dark/light/system, dar/geniş, zoom, Tab/Shift+Tab/popup/modal focus-return, VoiceOver isim/tek status duyurusu ve gerçek screenshot. Fixture snapshot yerine native kanıt; screenshot toleransı kusuru gizlemek için artırılmaz.
- L12 gerçek mikrofon deny→allow, kısa Türkçe utterance, duyulur TTS+interrupt, hangup owned cleanup; kullanıcı gerçek browser profilinde login/2FA kendisi, visible window ve takeover/resume. Hardware/OS/login adımı gereken satır açık bekleyen kabul; başka kapıların devamını engellemez.
- Kullanıcı Fusion'da kendi seçtiği üç günlük işi tamamlar; her biri task/receipt/çıktı, süre, hata, human intervention ve açık known issue olarak kaydedilir. Bu işlere root manual düzeltme katkısı varsa ayrı ölçülür; bütün gerekli yüzeyler kanıtlanmadan günlük sürüm hazır ilan edilmez.
