## Minimal sözleşme ve tasarım

1. **Checkpoint kimliği.** Canonical workspace+profile/conversation+plan identity (Paket 2) store anahtarıdır; kullanıcı plan adını filename'e koyma. Stable digest/encoded key traversal/collision engeller; sadece plan_id kullanılan legacy API için explicit scoped adapter ve ambiguous lookup hatası. Yeni payload identity alanı path ile doğrulanır. Legacy sanitized path yalnız fallback read; payload plan_id/root/conversation tam eşleşmeden migration yapılmaz. Collision legacy dosyada kaybolmuş checkpoint yeniden icat edilmez; eldeki geçerli kayda typed warning. `find_resumable` path'i doğrudan parse eden private helper, yeni adı plan_id olarak tekrar hashlemez; eski/yeni aynı payload identity dedup.
2. **Atomic CAS.** `WorkflowCheckpoint` additive `storage_revision` (step.revision ve plan schema ayrı), store save/checkpoint expected_revision → committed revision veya typed conflict. Writer `_PlanRun` son revision'ı saklar, ancak committen sonra artırır. Tek stable sibling lockfile üzerindeki OS process lock + aynı-process/thread lock read-current/check/CAS/write/replace'i birlikte korur; target inode'a lock koyma (replace inode değiştirir). Memory store mevcut fcntl lock yaklaşımını önce incele/reuse; memory DB exclusive-lock politikasını checkpoint için kör kopyalama. Platform adapter: POSIX/Windows gerçek lock semantics, desteklenmeyen lockta sessiz güvenlik iddiası yok.
3. **Durability.** Aynı directory'de exclusive unique temp, write→flush→file fsync→atomic replace→directory fsync (platform desteklediğinde); finally yalnız bu writer'ın temp'ini temizle. Rename öncesi failure eski geçerli target'ı korur. Rename sonrası directory fsync failure committed-but-durability-uncertain sonucu: kör retry revision artırıp duplicate değil, committed revision yeniden okunur. Supported durability capability teşhisi, keyfi garanti yok. Aynı küçük atomic writer job receipt'e reuse edilebilir; store CAS/immutable receipt politikaları ayrı kalır. Async caller disk transaction'ı `to_thread`+owned completion ile çalıştırır; cancellation başladığı transaction sonucunu belirsiz bırakmaz.
4. **Schema migration ve hata ayrımı.** Açık outer v1/v2/v3/v4→current migration functions, nested plan schema ayrıca validation; absent legacy version bilinen fixture ile karşılanır, future v999 failclosed UnsupportedSchema. Missing/Corrupt/IdentityMismatch/Conflict/IO ayrı typed load result; mevcut None facade gerekiyorsa yalnız compatibility caller, resume UI gerçek nedeni alır. Bozuk/future dosya overwrite edilmez. Malformed revision/boolean/negative, inconsistent completed IDs/dependency graph da validation. Privacy no raw tool args/prompt/source new checkpoint fields.
5. **Recovery admission ve effect receipt.** Existing WorkflowCheckpoint/StepCheckpointEvidence additive minimal effect receipt `(attempt, step, tool_call_id, target identity, idempotency key/remote receipt ref, prepared/in_flight/observed terminal, source revision)`; ham command/prompt/secret argüman yok. Mutasyon başlamadan intent durable save başarılı olmalı; completion observation sonrasında receipt kaydedilir. D01 submission dedup tool effect dedup değildir. Provider destekliyorsa aynı external idempotency key/retrieve receipt kullanılır; destek yoksa exactly-once vaat edilmez, response-lost sonucu ambiguous+OBSERVE_FIRST/NEVER sınırı olur.
6. **Resume önce gözlem.** Interrupted dış mutation adımı RUNNING/ambiguous ise read-only scoped observation zorunlu; kaynak fresh hash/revision ve gerçek external receipt/status aynı target/account için doğrulanır. Completed effect görülürse yeniden çalıştırmadan completed+fresh evidence; dependent source değişirse `dependent_ids/invalidate` mevcut dalı açar fakat eski dış etkiyi replay etmez. Yokluk kanıtı güvenilir/idempotency güvenli ise explicit fresh authorization ile tek execution; bilinmiyorsa pause+somut karar. “Gözlem bütçesi az” diye dış mutasyon yoluna geçiş yok; mevcut `can_repair_local_inventory` dar lokal kanıt şartı ayrı kalsın. `_PlanRun.verify` dış expected_effects'i silmek yerine observation evidence resolver ile doğrular, unsupported/unverified success olmaz. NEVER geçmişi gözlenebilir, kendiliğinden execute olmaz.
7. **Structured failure.** `ToolResult`/`ModelResult`/`AgentOutcome` additive failure category/code ve effect uncertainty; tools registry, provider timeout/contract, approval denied/blocked sınırında üretilir, `ToolUse` gerçek kayıtlarına taşınır. `classify_failure` genuine structured evidence→typed verification→unknown sırası; prose sınıflandırma ancak eski kayıtta diagnostic fallback, execution/retry grant vermez. Paket 1 FailureEvidence/RepairLedger authority reuse, yeni hata defteri yok; metinde “permission” görmek permission kategorisi değildir.
8. **Owned cancellation protokolü.** Turn owner `(session, attempt)` kendisine ait child/provider watchers/tool invocations/process/job handles listesine sahip; yeni global scheduler yok. Stop correlated idempotent request: stopping ack ve cleanup tamamlanınca cancelled terminal/status (legacy tur.calistir nihai sonucu korunur). Host state running→stopping→cancelled/cleanup_failed; accepted ve complete ayrılır. Cancel yeni mutation admission kapatır, pending approval/questions Paket 5'ten invalidates; owned child/streams cancel+await, foreground shell process group TERM→bounded grace→KILL→reap+stdout drain. Provider cancellation remote rollback demek değildir, unknown effect receipt kalır. UI terminal ancak backend cleanup sonucu; başka session/dev/terminal süreçlerine dokunmaz.
9. **Thread/process yönetimi.** `ToolRegistry.execute` cancellable sync invocation future'ını owned/shielded olarak takip eder, event set sonrası cooperative finish await; subprocess kullanan araç event poll veya injected owned process runner alır. Thread zorla öldürülemez; cleanup timeoutta cleanup_failed/remaining-effect uncertainty, false stopped yok. Mevcut ProcessManager'ın ortak process-tree stop primitive'ini engine/tools alt katmana core protocol üzerinden taşı/reuse; tools→appserver import yok. Yeni ikinci process manager değil küçük shared lifecycle helper. Spawn ile register arası cancellation race process orphan bırakmaz; liveness-only cancelled watcher'ın failure consumer statusunu zehirlemez.
10. **Jobs sahipliği ve restart.** Mevcut job dosyaları/JobCompletion otoritesi owner scope+start identity/process token ile additive genişler; ID collision exclusive creation ile önlenir, legacy 8hex parsing desteklenir. PID+root tek başına owner/liveness kanıtı değildir; yeniden açılmada process start identity doğrulanamıyorsa kill yok, status unknown. Job stop exit=143 dosyası yazmadan termination/reaping kanıtlar; observed termination code/cleanup result immutable receipt, duplicate stop aynı sonucu. Detached işi turn cancel kapsamına alma kararı ownership politikasında açık: mevcut kullanıcı “arka plan” seçimi bağımsız mı turn-owned mı metadata'da; tüm root işleri tarayıp öldürme yok. Legacy sahipliği bilinmeyen iş kullanıcı açık job stop dışında otomatik kill olmaz.
11. **Liveness singleflight.** Existing `watch/ping_for` aynı mekanizma kalır; session/turn injected coordinator key gerçek endpoint/model/account config revision (secret değeri değil). Aynı health epoch'ta üç waiter bir ping task'ı share; `shield` cancelled waiter owner ping'i bozmaz, owner close ping cancel+await. Result TTL/cooldown existing measured CHECK_AFTER/RECHECK budgets, injected clock; cached stale/credential revision değişimi invalidates. Web/unsupported provider genuine capability exclusion korunur. Ping metrics physical invocation/usage/cost ayrı health-purpose, Paket 7 unknown usage ayrımı; user model-turn hakkını sessiz tüketme veya ücretsiz sayma yok. Ping başarısı ana uzun çağrının tamamlandığı kanıtı değildir.
12. **UI/resume görünürlüğü.** Existing ExecutionCheckpointSaved/plan step/status ve submission receipt additive revision/phase/observed effects/stale dependencies/recoveryRequired/cleanup status; `useSessions.stop` backend terminal bekler, pending retry aynı ID. Transcript undo, ChangeSet rollback ve external effect history farklı; cancellation/restore dış MCP eylemi geri almış gibi görünmez. Journal deletion yalnız kendine ait completed/recorded cancellation state doğrulandıktan sonra; ambiguous checkpoint/effect kayıtları terminal caption yüzünden silinmez. Recovery UI gerçek tipli neden ve gözlemlenecek target'ı gösterir, unsupported schema devam düğmesini kapatır.
